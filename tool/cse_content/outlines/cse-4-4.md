# Course: Software Engineering  (level id "deep-cse-4-4", lesson ids "deep-cse-4-4-01".."-25")
Builds on Structured Programming (deep-cse-1-2), OOP (deep-cse-2-1, whose lesson 25 previews UML class diagrams, SOLID and a few patterns) and DBMS (deep-cse-4-2).
Requirements elicitation, DFDs, feasibility study and detailed system analysis belong to System Analysis & Design (deep-cse-4-6): mention and point there.
Focus: process models, agile/Scrum, UML basics, design principles and patterns, testing, version control, project management, estimation, quality, maintenance.
01 What software engineering is: program vs software product, software crisis and 1968 NATO conference, famous failures, software characteristics (does not wear out, deteriorates with change), SE layers (quality, process, methods, tools), ethics, course map
02 Software process and the SDLC: generic framework activities (communication, planning, modeling, construction, deployment), umbrella activities, Sommerville's four activities, SDLC phases, what a process model is, prescriptive vs agile
03 Waterfall and V-model: phases and sign-offs, Royce 1970, when waterfall fits, drawbacks (late working software, costly change), cost of fixing defects later, V-model pairing of development and test levels, verification vs validation
04 Incremental, iterative and prototyping models: increments vs iterations, delivering core first, throwaway vs evolutionary prototypes, UI mockups, risks of prototyping, worked example of a release plan
05 Spiral, RAD, Unified Process and choosing a model: Boehm's risk-driven spiral and its four quadrants, RAD and timeboxing, RUP phases (inception, elaboration, construction, transition) and disciplines, comparison and how to choose
06 Agile and Extreme Programming: why agile appeared, Agile Manifesto 2001 (4 values, key principles), iterative delivery, XP values and practices (user stories, small releases, pair programming, TDD, continuous integration, refactoring, collective ownership, sustainable pace), agile myths
07 Scrum and Kanban: Scrum roles (Product Owner, Scrum Master, Developers), events (Sprint, Planning, Daily Scrum, Review, Retrospective), artifacts (Product/Sprint Backlog, Increment, Definition of Done), user stories, story points, velocity, burndown chart; Kanban board, WIP limits, lead time; Scrum vs Kanban
08 Requirements engineering essentials: functional vs non-functional requirements, user vs system requirements, SRS structure (IEEE 830 / ISO/IEC/IEEE 29148), qualities of a good requirement, acceptance criteria (Given-When-Then), validation, traceability, change; elicitation/feasibility only briefly (see deep-cse-4-6)
09 UML overview and use case modeling: why modeling, history (Booch, Rumbaugh, Jacobson, OMG), structure vs behavior diagrams, use case diagram (actors, system boundary, include, extend, generalization), writing a use case description
10 Class diagrams for design: class notation, visibility, attributes and operations, multiplicity, association, aggregation, composition, generalization, realization, dependency, finding classes from nouns, object diagrams
11 Sequence, activity and state diagrams: lifelines, synchronous/asynchronous/return messages, activation, alt/opt/loop fragments; activity diagram with decisions, fork/join, swimlanes; state machine diagram with events and guards; component and deployment diagrams briefly
12 Software design fundamentals: architectural vs detailed design, abstraction, decomposition and modularity, information hiding, coupling (data to content) and cohesion (coincidental to functional), worked comparison
13 Software architecture styles: what architecture is, layered, client-server, MVC, pipe-and-filter, event-driven/publish-subscribe, monolith vs microservices, REST APIs briefly, quality attributes drive choices
14 Design principles: SOLID (SRP, OCP, LSP, ISP, DIP) with small examples, DRY, KISS, YAGNI, Law of Demeter, composition over inheritance
15 Design patterns: what a pattern is, Gang of Four 1994 (23 patterns, creational/structural/behavioral), Singleton, Factory Method, Builder, Adapter, Decorator, Facade, Observer, Strategy, anti-patterns, when not to use patterns
16 Construction, code quality and refactoring: coding standards and naming, comments, code smells, refactoring steps, code reviews and Fagan inspections, static analysis, technical debt
17 Version control with Git: why version control, centralized vs distributed, repository, commit, staging, branch, merge, conflicts, remote, push/pull, pull requests, branching strategies (Git flow, trunk-based), tags and semantic versioning
18 Software testing fundamentals: error, fault and failure, verification vs validation, seven testing principles, test levels (unit, integration, system, acceptance), integration strategies (top-down, bottom-up, stubs, drivers), alpha and beta, test case anatomy
19 Black-box testing techniques: equivalence partitioning, boundary value analysis, decision tables, state transition testing, use case testing, worked examples
20 White-box testing: control flow graph, statement, branch and path coverage, McCabe cyclomatic complexity (three formulas), basis path testing worked example, mutation testing briefly
21 Test automation, TDD, CI/CD and DevOps: unit test frameworks, assertions, test doubles (stub, mock), TDD red-green-refactor, regression testing, test pyramid, non-functional testing types, continuous integration, delivery vs deployment, DevOps culture
22 Software project management and scheduling: 4 Ps, project planning, work breakdown structure, Gantt chart, activity network, critical path method worked example, PERT three-point estimate, Brooks's law, team structures, tracking
23 Software estimation: why estimation is hard, cone of uncertainty, LOC, function points (Albrecht, weights, VAF) worked example, basic COCOMO (organic, semi-detached, embedded) worked example, COCOMO II note, expert judgment and planning poker
24 Risk management and software quality: risk identification, probability x impact, RMMM, quality definitions, McCall factors, ISO 9126 and ISO/IEC 25010, metrics (defect density), SQA, reviews, CMMI levels, ISO 9001, Six Sigma
25 Maintenance, configuration management and evolution: maintenance types (corrective, adaptive, perfective, preventive), Lehman's laws, legacy systems, reverse engineering and reengineering, software configuration management (baselines, change control board, releases), documentation, course recap and what next
