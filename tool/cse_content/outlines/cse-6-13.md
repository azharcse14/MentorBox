# Course: System Design  (level id "deep-cse-6-13", lesson ids "deep-cse-6-13-01".."-25")
Builds on Computer Networks (deep-cse-4-3: lessons 05-06 HTTP, caching, CDNs; 08 DNS; 11-16 TCP/UDP), Database Management Systems
(deep-cse-4-2: lessons 17 indexing, 20-24 transactions, NoSQL), Web Engineering (deep-cse-5-3: lessons 18 REST, 20-22 sessions, auth,
web security, 23 performance), Computer Security (deep-cse-6-2: TLS, hashing) and above all Distributed Systems (deep-cse-6-3: 06 queues,
14-15 replication and quorums, 16 consistency, 17 CAP/PACELC, 19 Raft, 21 sagas, 22 sharding and consistent hashing, 25 caching patterns,
retries, circuit breakers, SLOs). Those are recapped in a paragraph and cited by lesson id, never re-taught. Here the focus is practical
large-scale design: turning a vague product idea into requirements, numbers, building blocks and a defensible architecture, then the
classic case studies. System Analysis & Design (deep-cse-4-6) decides what to build; this course decides how it survives a huge crowd.
Point forward instead of going deep: Cloud Computing (deep-cse-7-3), Advanced Database Systems & Big Data (deep-cse-7-2), Fault Tolerant
Systems (deep-cse-7-10), Data Engineering (deep-cse-7-11), Information Retrieval (deep-cse-7-9). Estimates checked with Python. Product
names (Redis, Memcached, Kafka, Cassandra, S3-style object storage, Nginx, Kubernetes) appear only as version-neutral examples; Bangladesh
companies (bKash, Daraz, Pathao, Chaldal) only as "a bKash-style wallet" style illustrations, never claims about their real internals.
01 What system design is and how to approach it: definition, tea stall vs 5,000-guest wedding, System Analysis & Design vs System Design vs Distributed Systems, high-level vs low-level design, what makes it hard (scale, failure, trade-offs, no single right answer), the step framework (clarify requirements, estimate, API, data model, high-level diagram, deep dives, bottlenecks and trade-offs), boxes-and-arrows vocabulary, course map
02 Requirements: functional vs non-functional, scoping questions to ask, users and read/write ratio, latency targets and percentiles (p50, p99 worked on 10 sample times), availability nines worked (99.9% = 8.76 h/year, 99.99% = 52.6 min/year), durability, consistency needs per feature, SLA/SLO recap (deep-cse-6-3-25), constraints (budget, team, compliance like keeping data in-country), worked requirement list for a Daraz-style shop
03 Back-of-the-envelope estimation: why rough numbers, powers of two and units (KB to PB), latency numbers every designer should know (memory vs SSD vs disk vs network, Dhaka-Singapore RTT), DAU to average QPS (10 M x 5 / 86,400 = about 580) and peak factor, storage per day/year with replication, bandwidth in and out, servers needed from per-server QPS, cache memory with the 80/20 rule, full worked photo-sharing estimate, common slips (bits vs bytes, forgetting replicas)
04 From one server to millions: the scaling journey: single server, splitting web and database, vertical vs horizontal scaling and their limits, stateless web tier and where session state goes, adding a load balancer, read replicas, cache, CDN, message queue and workers, multiple data centers, logging and metrics; each step with the problem it solves and the new problem it creates
05 Networking building blocks for designers: what happens when you type a URL (DNS, TCP, TLS, HTTP) recapped from deep-cse-4-3, round trips and why they dominate latency worked, keep-alive and connection pools, HTTP/1.1 vs HTTP/2 vs HTTP/3 in one paragraph each, real-time choices: short polling, long polling, Server-Sent Events, WebSockets (with message cost worked), proxies vs reverse proxies, when UDP is used
06 API design: REST resources and verbs recap (deep-cse-5-3-18), status codes that matter, request/response shape, pagination (offset vs cursor, why offset breaks at page 10,000), filtering and sorting, versioning, idempotency keys for POST (recap deep-cse-6-3-05), authentication tokens brief, rate-limit headers, REST vs GraphQL vs gRPC and when each fits, worked API for a ride-hailing app
07 Load balancing: why, layer 4 vs layer 7, algorithms (round robin, weighted, least connections, least response time, IP hash, consistent hashing) with small worked distributions, health checks (active vs passive), sticky sessions and why to avoid them, TLS termination, the load balancer as a single point of failure (active-passive pair, floating IP), DNS load balancing and global server load balancing (GeoDNS, anycast idea)
08 Caching in depth: why memory beats disk, where caches live (browser, CDN, reverse proxy, application, database buffer), patterns recap (cache-aside, read-through, write-through, write-behind, write-around; deep-cse-6-3-25), effective latency with hit ratio worked (0.9 x 1 + 0.1 x 10), eviction (LRU worked, LFU, TTL), sizing, invalidation and stale data, cache stampede and fixes (locking, early refresh, jittered TTL), hot keys, Redis vs Memcached as examples, what not to cache
09 CDNs and serving static content: static vs dynamic content, edge servers and points of presence, pull vs push CDN, Cache-Control and TTL, cache keys, invalidation vs versioned file names (app.3f2a.js), origin shield, bandwidth and latency savings worked, dynamic content acceleration brief, cost thinking, Bangladesh users fetching from nearby edges
10 Choosing a database: data shape and access patterns first, relational strengths (ACID, joins, constraints), NoSQL families (key-value, document, wide-column, graph) with one fitting use each, search indexes, time-series stores, object/blob storage for files, ACID vs BASE recap (deep-cse-6-3-17), polyglot persistence, decision checklist, worked choice for a wallet vs a chat app vs a product catalog
11 Data modeling, indexes and storage engines: modeling for queries, normalization recap vs deliberate denormalization, indexes speed reads and slow writes (worked lookup cost log2 of 1 billion = about 30), composite index and column order, B-tree vs LSM-tree engines (memtable, SSTables, compaction, write vs read amplification) in simple terms, which workload suits which, counters and the hot row problem
12 Scaling the database: replication recap (deep-cse-6-3-14/15), read replicas and replication lag, read-your-writes fixes, sharding recap (deep-cse-6-3-22) with practical shard-key choice (user id, tenant, geography, time), cross-shard queries and joins, resharding, celebrity/hot shard, unique ID generation (auto-increment trouble, UUID, ticket server, Snowflake-style 64-bit layout worked: 41-bit ms time gives about 69.7 years, 4,096 IDs per ms per machine), connection pooling
13 Message queues and asynchronous processing in practice: recap of brokers and logs (deep-cse-6-3-06), when to go async, job queue plus workers, fan-out to many consumers, delivery guarantees in practice (at-least-once plus idempotent consumers), ordering by partition key, retries and dead-letter queue, sizing workers with Little's law worked (L = lambda x W), backpressure, event-driven architecture, transactional outbox, scheduled and delayed jobs
14 Rate limiting: why (abuse, fairness, cost, protecting downstream), where (client, gateway, service), algorithms worked: token bucket, leaky bucket, fixed window (and its boundary burst), sliding window log, sliding window counter (weighted formula), distributed limiter with a shared store and atomic increment, race conditions, HTTP 429 and Retry-After, per-user vs per-IP vs global limits, OTP/SMS abuse example
15 Reliability and resilience: single points of failure, availability in series vs parallel worked (0.999^3, 1 - 0.01^2), redundancy, timeouts, retries with backoff and jitter recap, circuit breaker and bulkhead recap (deep-cse-6-3-25), graceful degradation and load shedding, health checks, backups and the 3-2-1 idea, RPO and RTO, disaster recovery options (backup-restore, pilot light, warm standby, active-active), multi-region trade-offs, chaos testing, point to deep-cse-7-10
16 Observability, deployment and security in design: logs, metrics, traces recap (deep-cse-6-3-25), the four golden signals, dashboards and alerts that matter, percentiles not averages, deployments: rolling, blue-green, canary with worked traffic split, feature flags, rollback, database migrations without downtime (expand and contract); security: authentication vs authorization, tokens, TLS everywhere, encryption at rest, secrets, least privilege, DDoS layers, OWASP recap (deep-cse-5-3-22)
17 Microservices in practice: monolith first, modular monolith, splitting by business capability, database per service, sync (REST/gRPC) vs async (events) communication, API gateway, service discovery, distributed transactions via sagas recap (deep-cse-6-3-21), containers and orchestration brief (point to deep-cse-7-3), the costs (network hops, debugging, data duplication), when not to split, worked split of a food-delivery app
18 Case study: URL shortener: requirements, estimation (100 M new URLs/month, read heavy 100:1), API, base62 math (62^7 = about 3.5 trillion codes), approaches (hash and truncate with collision check, counter/ID plus base62 worked encoding), database choice, redirect 301 vs 302 and analytics, cache for hot links, custom aliases and expiry, abuse prevention, scaling and bottlenecks
19 Case study: chat system: requirements (1-to-1, groups, online status, delivery and read receipts, history), connection layer with WebSockets and chat servers, finding which server a user is on, message flow step by step, message IDs and ordering per conversation, storage choice for huge message volume (wide-column, partition by conversation), offline users and push notifications, group fan-out limits, presence with heartbeats, end-to-end encryption brief, estimation
20 Case study: news feed: requirements, post publishing path, fan-out on write (push) vs fan-out on read (pull) worked with follower counts, the celebrity problem and the hybrid, feed cache layout (list of post ids), ranking brief, pagination with cursors, media via CDN, likes and counters at scale, estimation
21 Case study: notification system: channels (push via APNs/FCM, SMS gateways, email), requirements (millions per day, retries, no duplicates, user preferences, quiet hours), architecture (notification service, per-channel queues, workers, providers), templates, deduplication, retries and fallbacks (push fails then SMS), rate limits per user, tracking delivery, cost of SMS worked, Eid-campaign spike example
22 Case study: search autocomplete (typeahead): requirements (top 5 suggestions within about 100 ms), trie worked with small word counts, storing top-k at each node, building the trie offline from query logs, sampling, updating, serving from cache, sharding by prefix and uneven letters, filtering bad suggestions, multi-language (Bangla and English) note, point to deep-cse-7-9
23 Case study: video streaming platform: requirements, upload flow (pre-signed upload to object storage), transcoding pipeline as a DAG (resolutions and codecs), storage estimation worked, adaptive bitrate streaming (segments, manifest, player switching), CDN for delivery and popularity long tail, view counting, metadata DB, cost thinking
24 Case study: ride-hailing and proximity service: requirements, location updates estimation (drivers every 4 s), why plain SQL lat/long range scans struggle, geohash worked (precision and neighbours), quadtree idea, in-memory location store, matching flow step by step (request, nearby drivers, offer, accept, lock), trip state machine, surge pricing brief, ETA and maps brief, sharding by city/area, hot zones
25 Capstone and interview playbook: designing a flash-sale e-commerce system (Daraz 11.11-style): requirements, estimation, CDN and cache for product pages, queue-based checkout, preventing overselling (atomic decrement, reservations with expiry), payment with idempotency and sagas, rate limits and virtual waiting room, failure drills; then the interview playbook (time plan, what to say, common mistakes, trade-off phrases), course recap and what next (deep-cse-7-3, deep-cse-7-2, deep-cse-7-10, deep-cse-7-11, deep-cse-7-9)
