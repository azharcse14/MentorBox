# Course: Distributed Systems  (level id "deep-cse-6-3", lesson ids "deep-cse-6-3-01".."-26")
Builds on Operating Systems (deep-cse-4-1: lessons 04-07 processes, IPC, threads; 12-17 synchronisation and deadlock), Database
Management Systems (deep-cse-4-2: lessons 20-24 transactions, 2PL, recovery, NoSQL/CAP/2PC preview), Computer Networks (deep-cse-4-3:
lessons 04 and 08-11 client-server/P2P, DNS, sockets, TCP/UDP) and Computer Security (deep-cse-6-2: lessons 16-19 MACs, signatures, TLS).
Those are only recapped; here the focus is what changes when many machines with no shared memory and no shared clock must cooperate.
Later courses go deeper, so keep these light and point forward: System Design (deep-cse-6-13), Cloud Computing (deep-cse-7-3), Parallel &
High Performance Computing (deep-cse-7-5), Fault Tolerant Systems (deep-cse-7-10), Advanced Database Systems & Big Data (deep-cse-7-2),
Blockchain (deep-cse-9-2). Tanenbaum & van Steen / Coulouris style, with small worked traces (clocks, message counts, quorums, hashing)
checked with Python. Product names (Kafka, ZooKeeper, etcd, Cassandra, HDFS, gRPC) appear only as version-neutral examples.
01 What a distributed system is: definition (independent computers that appear as one coherent system), no shared memory, no global clock, independent failures, why build them (sharing, scale, availability, geography), examples (web search, bKash-style wallet, ride sharing, online games), Lamport's "a computer you didn't know existed" quip, course map
02 Goals and the fallacies: resource sharing, distribution transparency (access, location, relocation/migration, replication, concurrency, failure) and its limits, openness (interfaces, interoperability, portability), scalability (size, geographic, administrative), scaling techniques (hide latency, partition, replicate), latency numbers worked (Dhaka-Singapore RTT), the eight fallacies of distributed computing
03 Architectures: architectural styles (layered, object/service-based, resource-based REST, event-based/publish-subscribe, shared data-space), client-server, multi-tier (2-tier, 3-tier), thin vs fat client, peer-to-peer (unstructured vs structured), hybrid (BitTorrent tracker, CDN edge), middleware as the glue, interceptors, edge computing brief
04 Communication and message passing: recap TCP/UDP sockets (deep-cse-4-3), message passing primitives send/receive, synchronous vs asynchronous, blocking vs non-blocking, transient vs persistent communication, marshalling and serialization (JSON vs binary/protobuf idea), byte order, message size worked, request-reply protocol with timeouts and duplicate filtering
05 Remote procedure call: the idea (call a function on another machine), client stub and server stub, the 10 steps, parameter passing (no pointers, copy/restore), IDL, binding and discovery, failure cases (lost request, lost reply, server crash, client crash), maybe/at-least-once/at-most-once/exactly-once, idempotent operations and idempotency keys worked (a double-charge example), REST and gRPC as modern RPC
06 Message queues and publish-subscribe: message-oriented middleware, decoupling in time and space, queues and brokers, point-to-point vs pub-sub, topics and subscriptions, push vs pull consumers, acknowledgement and redelivery, at-least-once delivery plus idempotent consumers, ordering per partition, dead-letter queue, append-only log idea (Kafka-style), consumer groups, backpressure, an SMS/notification fan-out example
07 Naming: names, identifiers and addresses, flat naming (broadcast, forwarding pointers, home-based like mobile IP), distributed hash tables and Chord idea (finger table, O(log N) hops worked), structured naming and DNS-style resolution recap (iterative vs recursive, caching, TTL), attribute-based naming (directory services), service discovery and health-checked registries
08 Physical clocks and clock synchronization: why time is hard, quartz drift (ppm worked: 10 ppm = 0.864 s/day), skew vs drift, UTC, GPS, Cristian's algorithm worked (T + RTT/2, accuracy bound), Berkeley algorithm worked (averaging with fault-tolerant cutoff), NTP offset and delay formulas worked with four timestamps, strata, never jump backwards (slewing), PTP brief
09 Logical clocks: why order matters more than time, happened-before relation (three rules), concurrent events, Lamport clock rules, worked three-process trace, C(a) < C(b) not implying a -> b, total order with process-id tie-break, totally ordered multicast idea (bank replica example)
10 Vector clocks: the limitation Lamport clocks leave, vector clock rules, worked three-process trace, comparing vectors (<=, <, concurrent), detecting conflicts in replicated data (shopping cart), causal ordering of messages with vector timestamps, size cost (N entries), version vectors and dotted versions brief
11 Global state and snapshots: why a global snapshot is hard, cuts, consistent vs inconsistent cuts, channel state, Chandy-Lamport algorithm (marker rules, FIFO channels) worked with two processes and money in transit, uses (checkpointing, deadlock and termination detection, garbage collection), distributed deadlock detection brief
12 Distributed mutual exclusion: requirements (safety, liveness, fairness), centralized coordinator (3 messages per entry), Lamport's algorithm 3(N-1), Ricart-Agrawala 2(N-1) worked with timestamps and deferred replies, token ring (0 to N-1 messages), quorum/Maekawa idea (sqrt N), comparison table with failure behaviour, lock services with leases in practice
13 Election algorithms: why elect a coordinator, assumptions (unique ids, crash failures), bully algorithm worked (message counts best and worst), ring algorithm worked (Chang-Roberts style, 2N-ish messages), election in wireless and large systems brief, leases and split-brain warning, consensus-based leader election preview (lesson 19)
14 Replication I, why and primary-backup: reasons (availability math worked: 1 - 0.01^3), performance, the consistency cost, replica placement, primary-backup (single leader), synchronous vs asynchronous vs semi-synchronous replication, replication lag and its anomalies, failover and fencing, log shipping, multi-leader replication and write conflicts (two data centers), conflict resolution (last-writer-wins, merge, CRDT idea)
15 Replication II, leaderless and quorums: Dynamo-style leaderless replication, N, W, R, R + W > N overlap worked (N=3, W=2, R=2), what each choice favours, read repair, anti-entropy with Merkle trees idea, sloppy quorum and hinted handoff, last-writer-wins with clock skew danger, when quorums still return stale data
16 Consistency models: data-centric vs client-centric, strict (ideal), linearizability (real-time order, single-copy illusion) worked with a register history, sequential consistency (same order for all, program order kept), causal consistency, FIFO/PRAM, eventual consistency, client-centric guarantees (read-your-writes, monotonic reads, monotonic writes, writes-follow-reads), choosing a model
17 CAP and PACELC: the CAP theorem stated carefully (during a network partition a system must choose consistency or availability; Brewer 2000, Gilbert and Lynch 2002 proof), what C, A and P mean precisely, why "pick two of three" is misleading, CP vs AP examples, PACELC (else latency vs consistency), BASE vs ACID recap, a Dhaka-Chattogram partition worked
18 Consensus I, the problem, FLP and Paxos: agreement, validity, termination, uses (leader, log, configuration, locks), synchronous vs asynchronous vs partially synchronous models, FLP impossibility stated carefully (no deterministic algorithm guarantees termination in an asynchronous system with even one crash fault; safety can still always hold), majority quorums and 2f+1, Paxos roles and two phases (prepare/promise, accept/accepted) walk-through, why proposal numbers matter, Multi-Paxos idea
19 Consensus II, Raft: replicated state machine, terms, follower/candidate/leader, randomized election timeouts, RequestVote and the up-to-date log rule, leader election walk-through with 5 nodes, AppendEntries and log replication walk-through, commit when stored on a majority, safety intuition, leader crash and log repair, membership change brief, etcd/Consul-style use
20 Fault tolerance and failure models: fault, error, failure, dependability (availability, reliability, safety, maintainability), MTTF/MTTR availability worked, failure models (crash, fail-stop, omission, timing, response, arbitrary/Byzantine), failure detection with heartbeats and timeouts (worked trade-off), redundancy (information, time, physical), process groups, Byzantine generals and the 3f+1 bound worked, BFT idea, checkpoint and message logging brief
21 Distributed transactions: ACID recap, why one bKash transfer may touch two databases, atomic commitment, two-phase commit worked (prepare/vote/commit, message count 4(N) style), coordinator failure and the blocking problem, logging in 2PC, three-phase commit idea and why it is rarely used, distributed locking and 2PL recap, sagas with compensating actions worked (ride booking), orchestration vs choreography, outbox pattern brief
22 Partitioning, sharding and consistent hashing: why partition, by key range vs by hash, hot spots and skew, hash mod N and the rebalancing problem worked (moving keys when N changes), consistent hashing ring worked (which node owns which key, what moves when a node joins), virtual nodes, secondary indexes (local vs global), request routing, rebalancing strategies
23 Distributed file systems: goals, NFS-style remote access recap, client caching and consistency, GFS/HDFS-style design (one metadata master/NameNode, chunk/data servers, large blocks, 3 replicas), read path and write path step by step, rack-aware replica placement, block size math worked, single master trade-off and high-availability fix, object storage contrast
24 MapReduce and batch processing: data locality, the map, shuffle and reduce phases, word count worked end to end on Bangla/English sentences, combiners, partitioner (hash mod R), handling worker failures by re-execution, stragglers and backup tasks, limits of MapReduce, Spark-style in-memory DAGs and stream processing brief (point to deep-cse-7-2 and deep-cse-7-5)
25 Caching, CDNs, microservices and observability: cache-aside, write-through, write-back, invalidation and TTL, cache stampede, CDN recap, monolith vs microservices, service boundaries, API gateway, service mesh brief, retries with exponential backoff and jitter worked, timeouts, circuit breaker, observability (logs, metrics, traces), correlation ids, RED/USE ideas, SLI/SLO/error budget worked
26 Capstone and wrap-up: designing a fault-tolerant mobile-wallet backend for Bangladesh (invented "DeshPay", Dhaka and Chattogram data centers): requirements, partitioning by account, replication and Raft-backed ledger, idempotent transfer API, sagas for cross-service flows, queues for notifications, consistency choices per feature, failure drills (DC partition, node crash), observability, course recap and what next (deep-cse-6-13, deep-cse-7-3, deep-cse-7-5, deep-cse-7-10, deep-cse-7-2, deep-cse-9-2)
