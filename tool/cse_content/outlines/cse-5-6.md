# Course: Embedded Systems  (level id "deep-cse-5-6", lesson ids "deep-cse-5-6-01".."-26")
Builds on Microprocessors & Assembly (deep-cse-3-3: 8086, IVT, 8255/8253/8259, polling vs interrupts), Computer Peripherals & Interfacing
(deep-cse-3-8: UART frame basics, SPI/I2C intro, ADC/DAC types, sensors, relays, H-bridge, LED resistor), Computer Architecture (deep-cse-3-2:
von Neumann/Harvard, buses, memory hierarchy) and Operating Systems (deep-cse-4-1: scheduling, semaphores, mutex, RM bound intro). Those are
recapped in a line or two only. Focus here: the microcontroller as a whole system, embedded C on real registers, MCU peripherals programmed
with worked numbers (16 MHz AVR / Arduino Uno as the running example, STM32 and ESP32 where useful), firmware structure, RTOS, real-time
analysis, power, reliability, debugging, IoT and a capstone. All worked numbers checked with a script.
01 What an embedded system is: computer inside a product, dedicated function, examples (rice cooker, bKash POS, car ECU, pacemaker), embedded vs general-purpose, reactive and real-time, brief history (4004 for a calculator), hardware + firmware, course map
02 Characteristics, constraints and design metrics: unit cost vs NRE (worked break-even: NRE 50,000 vs 10,000, unit 5 vs 9 -> 10,000 units), power and energy, size, performance, time-to-market, reliability and safety, maintainability, metric trade-offs
03 Microprocessor vs microcontroller vs SoC: recap MPU (8086) needing external chips, MCU all-in-one, SoC (phone chip, ESP32, Raspberry Pi), DSP, FPGA and ASIC brief, Harvard bus recap, choosing by job
04 Inside a microcontroller: CPU core, flash, SRAM, EEPROM, clock sources (crystal, internal RC, PLL), reset sources, internal bus, peripheral blocks, pins and alternate functions, ATmega328P numbers (32 KB flash, 2 KB SRAM, 1 KB EEPROM, 16 MHz on Uno), reading a datasheet
05 MCU families at a concept level: 8051 and PIC brief, 8-bit AVR and Arduino (board vs chip vs IDE), 32-bit ARM Cortex-M (M0/M0+/M3/M4/M7, licensed cores, STM32), ESP32 (Wi-Fi + Bluetooth, dual core up to 240 MHz), RP2040 brief, 8-bit vs 32-bit, how to choose
06 Embedded C part 1, toolchain and types: why C, cross-compiler, linker, hex/bin, flashing, int size differs (16-bit int on AVR), stdint fixed-width types, unsigned overflow wrap, memory sections (.text, .data, .bss, stack, heap), const in flash, avoid malloc
07 Embedded C part 2, bit manipulation: binary/hex recap, masks, set (|=), clear (&= ~), toggle (^=), test (&), shifts, multi-bit fields (read-modify-write a 2-bit field), worked values on 0b10100000, macros like _BV, pitfalls (operator precedence, signed shifts)
08 Registers, memory-mapped I/O and volatile: peripheral registers at addresses, pointer cast access, AVR DDRB/PORTB/PINB, STM32 struct (CMSIS) style, why volatile (optimizer, ISR-shared variables, hardware registers), volatile is not atomic, read-modify-write hazards, const volatile
09 GPIO: input/output direction, push-pull vs open-drain, internal pull-up/pull-down, floating input, current limits per pin, LED resistor recap (200 ohm), 3.3 V vs 5 V tolerance, reading a button with pull-up (active low), Arduino pinMode/digitalWrite vs register speed
10 Debouncing and input handling: why contacts bounce (ms of chatter), hardware RC + Schmitt trigger, software debounce (delay, sample-every-5 ms counter needing 4 equal samples = 20 ms, state machine), edge detection, long press, keypad scan recap
11 Timers and counters: counter + prescaler + clock, tick time (16 MHz / 64 = 4 us), overflow (8-bit at N=64 -> 1.024 ms), compare match / CTC (1 Hz with N=256 -> OCR 62,499), input capture for measuring pulses, counter mode for counting events, millis() idea, non-blocking delays
12 PWM: duty cycle, frequency, average voltage (25% of 5 V = 1.25 V), fast PWM f = fclk/(N x (TOP+1)) (N=8, TOP=255 -> 7,812.5 Hz; N=64 -> 976.56 Hz), resolution vs frequency trade-off, servo 50 Hz (TOP 39,999, 1 ms/1.5 ms/2 ms = 2,000/3,000/4,000 ticks), LED dimming, motor speed, PWM + RC filter as DAC
13 ADC and DAC on a microcontroller: recap of sampling/Nyquist/SAR, Vref, resolution and step size (10-bit 5 V = 4.88 mV; 12-bit 3.3 V = 0.806 mV), V = reading x Vref / 1024, LM35 worked (62 -> 0.303 V -> 30.3 C), channels and MUX, sampling time, noise and averaging, ESP32 8-bit DAC, calibration
14 Interrupts on microcontrollers: recap 8086 IVT/8259, MCU vector table, enabling (global + local), flags, ISR rules (short, no delay/printf, volatile flags, clear the flag), latency and what adds to it, priorities and nesting (Cortex-M NVIC, tail-chaining), critical sections, atomic access to 16-bit variables on 8-bit MCUs
15 UART in firmware: recap frame, 9600 8N1 worked frame for 'A' (0x41, LSB first), 1.04 ms per char and 960 bytes/s, baud register UBRR = fclk/(16 x baud) - 1 (9600 -> 103, actual 9,615, error 0.16%; 115200 -> 3.5% error, why crystals like 14.7456 MHz), TTL vs RS-232 and USB-serial, interrupt RX with ring buffer, simple command protocol
16 SPI and I2C in firmware: SPI MOSI/MISO/SCK/CS, CPOL/CPHA modes, full duplex byte swap, 1 MHz -> 8 us per byte; I2C SDA/SCL open drain with pull-ups, 7-bit address 0x48 -> 0x90 write / 0x91 read, start/ACK/stop worked frame, 100/400 kHz, clock stretching, bus hang recovery, comparison UART vs SPI vs I2C, choosing
17 Sensors and actuators from the firmware side: digital vs analog vs bus sensors, HC-SR04 worked (1,160 us echo -> 19.9 cm, 58 us per cm), soil moisture, DHT-type sensors brief, calibration (two-point), filtering (moving average, worked spike 700 -> avg 551, median idea), driving relays/motors/servos with drivers recap, ramping, flyback reminder
18 Power management: where power goes (P ~ C V^2 f, lowering 3.3 V to 1.8 V -> about 30%), sleep modes (idle, power-down), wake sources, duty cycling worked battery life (15 mA for 1 s each 60 s, 10 uA sleep -> 0.26 mA avg -> 7,700 h, about 320 days; always-on 5.6 days), clock gating, turning off peripherals, LDO vs buck, brown-out detection
19 Watchdog timers and reliability: what can hang a device (infinite loop, stuck bus, EMI), watchdog counter and reset, feeding it in the right place, choosing timeout, windowed watchdog, reset-cause register, brown-out reset, fail-safe outputs, defensive firmware (range checks, timeouts, assert), field example
20 Memory, boot and firmware update: what happens at reset (reset vector, startup code copies .data, zeroes .bss, calls main), flash vs EEPROM endurance (AVR flash 10,000, EEPROM 100,000 cycles; writing once a minute kills 100,000 in about 69 days), wear levelling idea, bootloader (Arduino serial bootloader), ISP/SWD programming, OTA update, A/B slots, CRC/signature check, rollback
21 Super-loop to RTOS: foreground/background (super-loop + ISRs), cooperative multitasking with state machines and millis, when a super-loop fails (one slow job blocks all), RTOS idea, tasks and their states, tick interrupt, preemptive priority scheduling, context switch and per-task stacks, FreeRTOS flavour (xTaskCreate, vTaskDelay), RTOS vs Linux on embedded
22 RTOS communication and synchronization: shared data problem, queues, binary and counting semaphores, ISR-to-task signalling (deferred interrupt work), mutex vs binary semaphore, priority inversion (Mars Pathfinder 1997) and priority inheritance, deadlock brief, common RTOS bugs (stack overflow, starvation)
23 Real-time systems and scheduling analysis: hard/firm/soft, period, deadline, WCET, jitter, utilization U = sum C/T, rate-monotonic priorities, Liu-Layland bound n(2^(1/n)-1) (0.828 for 2, 0.780 for 3, about 0.693 for large n), worked sets (U = 0.6 passes; U = 0.786 fails the bound but response-time analysis R = 2, 4, 5 shows schedulable), EDF bound U <= 1, measuring WCET
24 Debugging, testing and the design process: printf/UART logging and its cost, LED and GPIO toggling, JTAG/SWD debug probe (breakpoints, watch, step), logic analyzer and oscilloscope, protocol decoding, unit testing on the PC, hardware-in-the-loop, design flow (requirements, HW/SW partitioning, prototype on dev board, custom PCB, test, certification), version control for firmware
25 IoT connectivity, safety and security: why connect, Wi-Fi/BLE/LoRa/cellular (NB-IoT, GSM SMS) trade-offs at a concept level, MQTT publish/subscribe idea, gateways and cloud, security threats (default passwords, open debug ports, unsigned firmware, plain-text traffic), secure boot, signed OTA, TLS idea, safety (fail-safe, standards like IEC 61508 named only), privacy
26 Capstone, smart irrigation for a Bangladesh farm: requirements (soil moisture, pump via relay, solar/battery, SMS/LoRa alert), MCU choice, block diagram, pins, sampling and calibration, control logic with hysteresis, state machine, power budget, watchdog, OTA, testing in the field, cost estimate, course recap and what next
